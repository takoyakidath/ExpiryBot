# ExpiryBot 設計書

お土産の賞味期限を管理するDiscord Bot。DiscordのチャットDBの代わりにNotionをDBとして利用する。

## 目的

- お土産をもらった/買った際に、Discord上のチャットで気軽に賞味期限を登録できる
- 賞味期限が近いお土産を毎日自動でリマインドし、食べ忘れを防ぐ
- 消費済みのお土産はワンクリック(リアクション)で管理から外せる

## 全体アーキテクチャ

- **言語/ランタイム**: TypeScript / Node.js
- **Discordライブラリ**: discord.js v14
- **DB**: Notion(`@notionhq/client`)。お土産の正データはすべてNotion DBに保存する
- **ローカル永続化**: SQLite(`better-sqlite3`)。Discordメッセージ ↔ Notionページの対応表として使用。これはNotionのキャッシュではなく、「どのDiscordメッセージへのリアクションがどのNotionページの完了操作に対応するか」を追跡するためだけの補助データであり、再起動しても消えないようファイルに永続化する
- **スケジューラ**: `node-cron`。毎日決まった時刻に通知ジョブを実行する
- **デプロイ**: Dockerイメージ化し、自宅サーバ/Raspberry Pi等で常時起動するコンテナとして運用する
- **設定(環境変数)**:
  - `DISCORD_TOKEN` — Botトークン
  - `NOTION_TOKEN` — Notion Integration Token
  - `NOTION_DATABASE_ID` — 対象データベースID
  - `REGISTER_CHANNEL_ID` — 登録専用チャンネルのID
  - `NOTIFY_CHANNEL_ID` — 通知先チャンネルのID
  - `REMINDER_DAYS` — 通知対象とする残り日数の閾値(デフォルト 7)
  - `NOTIFY_CRON` — 通知cron式(デフォルト毎日9:00)
  - `TZ` — タイムゾーン(デフォルト Asia/Tokyo)

## Notion データベース設計

| プロパティ名 | 型 | 内容 |
|---|---|---|
| 商品名 | Title | お土産の名前(パーサーが抽出した文字列) |
| 賞味期限 | Date | 抽出した期限日 |
| ステータス | Select(`未消費` / `消費済み`) | 完了リアクションでBotが更新する |
| 登録者 | Text | 登録したDiscordユーザーの表示名 |
| 登録日時 | Created time | Notion側の自動プロパティ |
| 元メッセージ | URL | 登録時のDiscordメッセージへのパーマリンク(トレーサビリティ用) |

初期セットアップ手順(実装計画側でREADME等に記載):
1. Notion Integrationを作成しTokenを発行
2. 上表のプロパティを持つデータベースを作成
3. データベースをIntegrationと共有(connect)
4. データベースIDを`.env`に設定

## 登録フロー

1. `REGISTER_CHANNEL_ID` で指定した専用チャンネルの通常メッセージを常時監視する(他チャンネルは対象外)
2. メッセージ本文からルールベースの簡易パーサーで日付を抽出する
   - 対応フォーマット(優先順に検出):
     - `YYYY年M月D日`
     - `YYYY/M/D` , `YYYY-M-D`
     - `M月D日`(年省略。今日より前の日付になる場合は翌年扱い)
     - `M/D`(同上)
   - 「賞味期限」「期限」等の接頭キーワードがあれば除去する
   - 日付として認識した部分を本文から取り除いた残り文字列をtrimしたものを商品名とする
3. 日付を抽出できた場合:
   - Notionに新規ページを作成(商品名・賞味期限・ステータス=未消費・登録者・元メッセージURL)
   - メッセージに ✅ リアクションを付与
4. 日付を抽出できなかった場合:
   - メッセージに ❌ リアクションを付与
   - フォーマット例をスレッド返信(または通常リプライ)で簡潔に案内する
5. 商品名が空になった場合(日付のみのメッセージ等)も抽出失敗として扱う

## 通知・完了フロー

1. `NOTIFY_CRON` で指定した時刻に日次ジョブを実行する
2. Notionからステータス=`未消費` かつ 賞味期限が「今日 + `REMINDER_DAYS`日」以内(期限切れ=今日より前の日付を含む)のページを取得する
3. 対象アイテムごとに1メッセージを `NOTIFY_CHANNEL_ID` に投稿する
   - 期限切れ(賞味期限 < 今日)の場合は「⚠️期限切れ」ラベルを付けて区別する
   - 投稿したメッセージに ✅ リアクションを付与しておく
4. 投稿ごとに SQLite へ `discord_message_id → notion_page_id` の対応を保存する
5. ✅リアクションが押されたイベントを監視し、対応表からNotionページを特定してステータスを`消費済み`に更新する
   - Bot自身が付けた初期リアクションはトリガーとして無視する(ユーザーによるリアクション追加のみ処理)
   - 同じアイテムが翌日以降も未消費のまま残っていれば、新しい別メッセージとして再度通知される(前日メッセージの対応表エントリは古いまま残るが、実害はない)

## エラーハンドリング方針

- Notion API呼び出し失敗時はログ出力し、Discord側には❌リアクション or 簡潔なエラーリプライで知らせる(ユーザー入力のリトライは手動で再度メッセージを送ってもらう想定)
- Bot起動時にSQLiteファイルが存在しなければ自動でテーブルを作成する
- 環境変数の必須項目が欠けている場合は起動時に例外を投げてプロセスを終了する

## スコープ外(YAGNI)

- OCRによる画像からの自動読み取り
- 複数サーバー(ギルド)対応(単一サーバー・単一登録チャンネルを前提とする)
- LLMによる高精度な自然文解析(将来的な拡張候補として構造だけは切り離しておく)
